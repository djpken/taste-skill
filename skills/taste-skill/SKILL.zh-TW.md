# tasteskill v2

模型做出的頁面常像它看過的所有頁面的平均值：置中的三行標題、上方小標籤、一排圖示卡片、柔和漸層、幾條細線、等寬字說明。沒有明顯錯誤，也沒有真正做過設計決定。

此 skill 用四種方式取代這些預設：

1. **腳本抽出方向，由你選擇。** 模型自行發想時總選該類別的預設風格。`scripts/draw.mjs` 從二十個研究方向抽出三個；你選能承載主題構想的方向，腳本再從 247 個真實網站提煉的資料庫抽出字型系統、色盤、主視覺與區段構圖。
2. **構想來自主題本身。** 研究中，最好與容易遺忘的網站之差別，是取自事物本身的概念。
3. **不靠裝飾的設計準則。** `scripts/inspect.mjs` 用真實瀏覽器量測、驗證規則。
4. **檢視自己的成品。** 三種寬度截圖、評審規準、修正、再看一次。

測試帶來一項警訊：移除裝飾只完成一半。拿掉標籤、細線與卡片卻沒有補入內容，頁面會顯得單薄；盲評者合理地偏好有模板痕跡但充實的頁面。另一半工作是實質內容：更大字級、整片色塊、主題世界的真實圖片，無論搜尋或繪製，以及每個區段的完整內容。此 skill 用來提供這些內容，不要為了節制而捨棄。

下列命令的 `<skill>` 指此 skill 資料夾。從專案根目錄執行，工作檔會放在該處的 `.taste-skill/`。腳本需要 Node 22+ 與已安裝的 Chrome、Edge 或 Chromium，不會安裝任何東西。`assets.mjs` 另需網路，不用 API key。

## 網頁或 App 畫面

先判斷工作類型。

- **網頁**供閱讀、捲動：到達頁、行銷或產品網站、作品集、活動、餐廳、單頁網站。依下方**執行流程**處理。
- **App 畫面**供工作：儀表板、管理或分析畫面、設定、帳務、待處理的收件匣或佇列、錢包、有篩選器的清單、編輯器或建構工具。依 **`references/app-screens.md`** 處理。它有自己的流程、抽選 `draw.mjs --app`、設計準則與 `inspect.mjs --app`。低調邊框、小標籤與重複面板在此正常；漸層、光暈、彩底方框圖示、彩虹圖表與虛構漂亮數字仍不允許。開始前完整閱讀該檔，下方網頁流程不適用。

展示 App 的產品網站屬於網頁；內部介面片段依 App 規則製作。為產品抽選一次 App 風格，放進獨立資料夾，保留網頁的色彩與字型：

```bash
node <skill>/scripts/draw.mjs --app --kind <kind> --brief "<the product>" --keep palette,type --out .taste-skill/app
```

把每個片段，包括主視覺即時畫面、功能裁切、圖表，做成該 App 的真實部分：`assets/app.css` 提供面板、表格、控制項；`assets/charts.js` 提供圖表。資料必須能核對加總，明說一項發現，再依網頁藍圖對圖片的方式裁切、縮放。像能工作的產品片段，是軟體網站最強的圖片；灰條與隨意數字最弱。若同時要求到達頁與後方儀表板，各走自己的流程，共用色盤與字型。

## 執行流程

依序進行。步驟 1–5 花幾分鐘，決定頁面品質。

### 1. 閱讀需求與專案

確認真實條件：主題、受眾、頁面唯一要促成的行動、技術、既有品牌的色彩／字型／標誌，尤其是**實際存在的影像**：自有照片或產品照、可展示的真實介面、能呼叫的圖像生成工具，或完全沒有。不要依賴手上沒有的圖片規劃。沒有自有圖片通常仍有素材：城市、街道、材料與歷史可能藏在開放典藏或博物館中，標示出處即可使用，見步驟 6 的 `scripts/assets.mjs`。

需求模糊時，自行判斷並用一行說明解讀；只有缺少事實導致無法工作，例如沒有產品名，才提問。

在筆記中**盤點主題**：列出八到十二項只屬於此客戶、競爭者沒有的事物。包括名稱與含義；地址、門牌、街道、街區及其瓷磚、招牌、油漆、店面字型、光線、天氣；需求中的座位、房間、離海分鐘數、價格、年份；獨有限制，如每月一批、冬季休業、預約制；材料與色彩；儀式與時刻，如五點點爐、七點渡輪；其世界中的時刻表、標籤、票券、招牌。步驟 4 從此清單找構想。盲測勝出頁面都來自這類項目，如名稱、所在街道、定義它的限制；落敗頁面常有良好構圖，卻只有類別共通構想。清單也是圖片搜尋清單，每個地點、材料與印刷物都能成為步驟 6 的查詢。

### 2. 寫出論述

設計前，依 `references/copy.md` §1，逐區段用一行寫出主張與證據。主張決定區段與順序。沒有主張的區段刪掉，避免主視覺、商標、三個功能、見證、價格、行動呼籲的固定順序。

### 3. 抽選方向

```bash
node <skill>/scripts/draw.mjs --sector <sector> --brief "<one line about the subject>" \
  --sections <roles in the order of your argument> [--tone <tone>] [--have <assets>] [--keep palette,type] \
  --options 3
```

命令抽出三個方向並印出摘要。逐一對照盤點：哪種構圖能承載客戶獨有的事物？選它，在筆記用一行說明理由。測試中，隨機方向不合主題是弱頁面最常見的原因。接著抽出完整方向表：

```bash
node <skill>/scripts/draw.mjs <the same arguments, without --options> --direction <chosen id>
```

- `--sector`：用 `node <skill>/scripts/draw.mjs --list sectors` 查詢，選最接近的。
- `--sections`：取自 `--list roles` 的角色：features、showcase、how-it-works、testimonial、proof、stats、pricing、faq、cta、footer、intro、about、work、gallery、list、contact。主視覺自動包含。
- `--tone` 選用：quiet、bold、warm、technical、playful、luxury、editorial。需求明說才傳入。
- `--have`：用逗號列出實際存在的素材：`photography` 是專案自有的場所、人物、作品照；`product-photo` 是特定產品照或能生成它的工具；`product-ui` 是真實截圖；另有 `illustration`、`video`。沒有就省略，抽選會避開依賴它們的構圖，並說明如何誠實填入圖片位置。軟體用 HTML 建自己的介面；沒有照片的產品可繪製，搭配真實世界圖片，不偽造產品照。開放典藏圖片非自有素材，不列入 `--have`。
- `--keep palette,type`：品牌已限定色彩或字型時使用。只抽構圖，把品牌值映射到角色。

命令輸出的**方向表**是此成品的藝術指導：

- **採用它。** 不要混入你原本就會做的版型。陌生感有價值，慣用版型正是此 skill 要避免的。
- 只在能說明理由時重抽單一欄位：`--redraw hero | type | palette | photos | scenes | section:<role> | direction`。例如違反明訂品牌限制、需要不存在的素材。不為求熟悉而重抽；報告記錄每次重抽。
- 區段無法承載真實內容時，不扭曲內容配合藍圖。例如只有一個價格卻要比較三種方案，或需要五段引言卻一段都沒有。用 `--alternatives <role>` 列出選項，選符合內容假設的，再用 `--redraw section:<role>=<id>` 取得。
- **核對色盤與主題。** 色盤也代表比例：底色、文字色、強調色、色域。若糖果粉彩不合泥煤威士忌、霓虹不合山屋，可重抽一次；主題有明確自有色彩，如材料、街道塗漆、窗外景觀，則保留抽選比例，採用主題色彩，並在報告說明。
- 隨時用 `node <skill>/scripts/draw.mjs --show` 重印。長工作階段每做一個區段前重讀。

### 4. 找出構想

方向決定構圖方式；構想決定頁面只屬於此主題。在筆記寫下此句，兩格都填入主題本身的事物後才開始做：

> 在此頁面，**[主題獨有的事物]** 成為 **[方向要求的表現手法]**。

第一格可從這些地方找：

- **產出。** 事物產生什麼？把真實產出當素材，如列印詩的相機用紙條承載文案。
- **物件或形狀。** 實體的剖面、輪廓？放大、裁切，做成框架或唯一母題。
- **名稱。** 字母能否容納照片、堆成牆、分到兩角？
- **場所。** 是否有一個景觀讓人想前往？
- **儀式。** 頁面能否隨捲動演出某個順序？
- **實物。** 世界中已有的票券、菜單、標籤、收據、邀請函、資料夾、手冊？
- **反面。** 哪個其他類別擁有此類別欠缺的感受？

第一格取自步驟 1 的盤點，避免類別共通概念。**競爭者測試：**把最近的真實競爭者放進句子，如兩條街外的麵包店、另一家橡木家具、同山的另一間山屋。仍適用就只是類別構想：每家麵包店都有麵包，以街道七扇門命名的這家才有七扇門。「乾淨現代」不算構想。研究評分最低者的構想記錄常是「標準公式之外沒有任何東西」。

**一項可互動內容。** 用構想讓訪客做一件事，或讓每次造訪有不同內容：選木材查看椅子；輸入名字，看它用鑄字廠字體呈現；設定貸款，讀出真實月付額；看山屋爐火是否點燃、末班渡輪倒數；選尺寸，比對房間。盲測勝出者都有，評審也最先提到。規則：用真實內容、手機拇指可操作、無腳本有簡單替代、不阻擋閱讀、只做一件事。步驟 6 納入頁面，不留到步驟 9 當動畫加入。

**場景也承載構想。** 方向表的捲動場景等待主題填入。製作前從盤點決定內容：飛越工作室自有片頭卡；沿貨運真實路線移動；展開到全螢幕的照片就是客人醒來的房間。填入誰都能用的圖片只會成為螢幕保護程式。

### 5. 撰寫文案

標記前先依 `references/copy.md` 用純文字寫完整文案稿：

- **任何寬度下每個標題最多兩行。** 選定句子前先算 copy.md §2 的字元預算。約 32 個字元可維持明確的大字級；研究主視覺標題中位數是 5 個字詞、32 個字元。
- 標題下 32–48px 放一個輔助句，同時顯示；不放首屏底部，也不被動畫延後。標題是名稱或比喻時，這句直說它是什麼。首屏提供真實按鈕，只有一項主要行動，名稱說明實際動作。
- **首屏用大字回答訪客第一個問題。** 活動：內容、時間、地點，日期放標題或次大字級；產品：是什麼、價格或用途；個人：是誰、做什麼。觀眾要找的陣容、菜單、房型、價格，都有獨立標題與導覽入口。
- **寫完整內容。** 需求要求的每個區段完整交付：全菜單與價格、每間房詳細資訊、所有講者與講題、價格包含項目、每個實際問題的答案。單薄區段最常讓簡潔頁面輸給繁忙頁面。
- 需求缺細節時補示例，如菜名、房名與價格、專案名，讓設計以完整密度呈現；報告列出待客戶確認者。不可虛構客戶、引言、評論、媒體、商標或業務統計等證據。

### 6. 先做靜態頁面

先關閉心中的動畫。依賴動畫才像完成的頁面還沒完成。順序：

1. **Tokens。** 把方向表的色彩與字型角色寫成 CSS custom properties，後續全部只引用 token。可從 `<skill>/assets/base.css` 開始：reset、token 名稱、流動字級、格線、焦點與選取樣式、動畫 helper，沒有自帶視覺風格。
2. **主視覺嚴格依藍圖。** 同時做桌面、手機。先讓大的夠大、小的夠小。
3. **每個區段依藍圖。** 使用專案內容，保留幾何、換主題。相鄰區段不同版型。**構想貫穿所有區段**，包括價格、FAQ、頁尾。研究中即使好網站也常首屏獨特、後面回到制式區塊。
4. **影像**依優先順序：
   1. 專案自有。
   2. 有工具時生成。
   3. **開放典藏中主題世界的真實圖片。** 有真實素材就找。用 `node <skill>/scripts/assets.mjs "<query>"` 搜尋 Openverse、Wikimedia Commons、Art Institute of Chicago、Met，預設只允許商用授權。搜尋盤點中的街道老明信片、街區地圖、材料特寫、行業版畫、同類博物館物件、植物圖譜、星圖。大幅、有目的地用：典藏照片作主視覺、版畫作母題、真實街道地圖作聯絡區段。選之前逐張看；`--get <ref>` 下載到 `assets/` 並記錄來源與授權，`--credits` 印出頁尾署名。找到的圖片展示客戶周遭世界，不冒充客戶自己的產品、房間、菜餚、人物或團隊。
   4. **從主題以程式碼繪製**沒有真實照片的物件、瓷磚、窗、產品介面。統一平面圖形語言，使用色盤真實色彩。
   5. 方向表照片，只用於真正適合通用圖的位置，如海邊屋的海景，不冒充主題。
   6. 只用字與色彩。

   專案有製程或產品影片／真實照片時，首屏大幅展示，約佔 40% 以上。頁面不寫圖片來源解釋或否認，如「這些都不是我們的酒吧」。圖說說圖片是什麼，署名小字放頁尾。需求中虛構的作品集，應逐件畫成完成作品定格，如有獨立字型的片頭卡、結尾畫面、海報，包含真細節，不以產品象形圖代替。

   **檢查器要求的最低量：**至少四張真實圖片，通常六至十二張，包括照片、典藏、地圖、版畫、影片、點陣藝術；軟體的介面裁切片段也算。SVG 不計入最低量：沒照片的可以畫，但仍需真實圖片。有真實影片就加一段，用 `assets.mjs --video "<query>"` 搜尋，以有 poster 的靜音循環播放。模型常因找圖費工而略過，缺少就不通過。

   `references/imagery.md` 說明搜尋、授權、署名、影片、繪圖、裁切、處理。
5. **可互動內容。** 把步驟 4 的內容放在能證明主張的區段，常是主視覺或預訂區。使用真實內容、手機拇指尺寸與無腳本替代。
6. **捲動場景。** 方向表抽到時依第 9 節，和所承載區段一起做：飛越作品的攝影機、展開全螢幕的圖片、隨捲動彎曲的字。從 `<skill>/assets/scenes/` 複製共用舞台與場景檔，填自有圖片與文字，設定頁面 tokens。場景決定頁長與每屏內容，屬構圖，現在就做，每輪都看，不留到最後。`references/scenes.md` 說明放入、填入、調整與檢查；`assets/scenes/demo/<id>.html` 是各場景可執行示例。
7. **充實度。** 桌面每屏當海報：一個主體與其內容。大部分只有空底色代表內容不足。每頁最多一次刻意休止，兩屏以上近空白會失敗。連續正文用完整文字色、至少 16px，灰色只給次要註記。
8. **外框。** 每個寬度有一對相等外邊界，各區段用滿頁面建立的寬度。文字在左半時，右半要有圖、第二欄、清單或數字。非對稱在格線內，不改外框；留空須在另一側有對應物。約半屏高以上不可全空；桌面區段距離 120–240px。每個主要區段以命名標題開始，首屏有 `h1` 頁面標題。「沒有清楚標題」「隨機空白」「全部擠一邊」是讀者先看到的錯，檢查器逐一量測。
9. **狀態與語意。** 真實連結、按鈕、可見焦點、alt 文字、獨立構圖的手機版。

需要決策細節時讀 `references/type.md`、`references/colour.md`、`references/layout.md`；下方原則是摘要。

### 7. 驗收關卡

```bash
node <skill>/scripts/lint.mjs <source files or folder>
node <skill>/scripts/inspect.mjs <url or path/to/index.html>
node <skill>/scripts/scenes.mjs <url or path/to/index.html>     # when the page has scroll scenes
```

`scenes.mjs` 在桌面、手機拍各場景固定區間的 0、10 … 100%，另拍減少動態版。方向表有場景時，`inspect.mjs` 也拍完整捲動影片 `desktop-film-NN.jpg`。桌面場景未啟動或停住會 `FAIL`。

`lint.mjs` 掃描禁用模式與制式句。`inspect.mjs` 在 1440、768、390 像素真實瀏覽器量測標題行數、字級、實際載入字型、色彩、線、陰影、漸層、對比、溢出及外框，包括等邊界、區段擠一側、空白、標題、無標題區段、貼邊文字。截圖存 `.taste-skill/inspect/`。修每個 `FAIL`；`WARN` 預設有錯，除非能用一句話向設計師辯護。重跑到零 `FAIL`，不爭辯或藏東西。檢查器用暫時本機伺服器提供本機檔案；若還需直接從檔案系統開啟，完成前也開一次 `index.html`。

### 8. 檢視

通過只代表沒量到禁用項，不代表好看。用圖片檢視器或 Read 工具開啟全部視窗尺寸截圖，依 `references/critique.md` 的十四輪檢視、Awwwards 權重分數、上限評估。照格式記錄，修前三個問題，重跑再看。最多三輪。

只依圖片判斷。截圖看得到的問題就存在，不論程式碼說什麼。

### 9. 加入動態

現在做必要的動態層，超過單一淡入。檢查器計算載入與捲動中實際移動的元素，少於八個失敗、少於十六個警告。捲動場景已在步驟 6 完成，周圍動態分四部分：

1. **方向表指定的招牌動作。** 一個做好；抽到的場景也可擔任。
2. **各區段的各部分入場。** 標題、文字、圖片依序延後 60–90ms，上移 16–32px 並變透明度，進入時觸發一次。不可整塊只有一個淡入；腳本失敗內容仍可見。
3. **各控制項回饋。** 按鈕、連結、卡片、互動內容具按下、懸停、焦點。
4. **一個移動影像。** 搜尋來的靜音影片、照片慢縮放或漂移，或主圖連動捲動。

只用 transform、opacity。每個動作有 `prefers-reduced-motion` 替代，保留內容、去掉位移。整屏變色或固定敘事屬構圖，步驟 6 就做，讓每輪都看得到。`references/motion.md` 有 tokens 與已測配方。最後再跑檢查器，逐張確認內容沒有未出現。

### 10. 回報

以下全部成立才回報；每項都曾在失敗測試被跳過：

- 最終頁面在 1440、768、390 的 `inspect.mjs` 為 **0 FAIL**。
- 最後修改後已看全部截圖，包含首屏之外。
- 有捲動場景時，最終 `scenes.mjs` 無問題，已看所有桌面、手機、減少動態圖表。
- 陌生人看首屏五秒能說出這是什麼、該做什麼。
- 每區段有標題，左右邊界一致，無整段空白。
- 最後評估依 `references/critique.md` §4 格式記錄。

簡短回報抽選方向名稱、seed、重抽與理由；構想句、互動內容；最終評分與不足；每張搜尋圖片及影片的標題、創作者、授權、來源頁與頁上署名位置，清單可用 `assets.mjs --credits`；哪些隨附照片、繪圖代替實拍供後續替換；上線前須換掉的示例。未執行的檢查不可宣稱通過。

## 設計準則

所有方向都適用，由 `inspect.mjs` 量測。

| 規則 | 做法 |
| --- | --- |
| **所有寬度標題最多兩行。** 包含 `h1`–`h6` 及首屏主文字，不論標籤。 | 先刪字，再加寬，最後才縮字級。 |
| **首屏有清楚標題**，使用唯一 `h1`；每區段有標題。 | 名稱加用途、產品加用途、活動加日期地點。 |
| **外邊界相等，不可區段擠一側、另半屏空白。** | 空間另一側放圖、第二欄、清單、數字。 |
| **不可空白超過約半屏高。** | 正常區段距離；刻意休止用圖片或整片色域，每頁一次。 |
| **陳述句是段落。** 大型引言用 `<p>` 或 `<blockquote>`，桌面最多 36px、手機 24px，約 25 個字詞、三行。 | 更大就算標題，受兩行限制。盲評把 42px 四行句子視為四行標題。 |
| **不用眉標。** 標題上不放小標、膠囊徽章、「New ·」。 | 整合進標題、首句或刪除。 |
| **真實程式碼以外不用等寬字。** | 用正文字型，數字對齊用等寬數字。 |
| **不加索引編號。** 不用 01 / 02 / 03、(001)、「Step 2」。 | 靠位置、大小、詞句；真正有順序用 `<ol>`。 |
| **不用細線。** 禁髮絲分隔、1px 外框、格線、十字、裁切記號。 | 空間、背景色階、尺寸變化、實心形狀。 |
| **不用漸層。** 背景、按鈕、文字均同。 | 平色或照片；照片文字下的中性遮罩例外。 |
| **靜止物不加陰影，不發光。** | 表面用色階區分，只有真正浮起的選單、對話框可用陰影。 |
| **不用助理慣用色盤。** 禁黃奶油底加陶土／鏽色，禁紫羅蘭、靛藍。 | 用抽選色盤。 |
| **不用微小大寫加寬字距標籤。** | 正常句首大寫、可讀字級。 |
| **不用上方圖示的功能卡或相同卡片列。** | 用抽選區段藍圖。 |
| **不用玻璃。** 禁背景模糊面板、浮動膠囊導覽。 | 普通橫列：文字標誌、少數連結、一項行動。 |
| **不用 emoji、漸層球、裝飾形狀、灰條假儀表板。** | 真圖、真介面片段，或不放。 |
| **標題不單獨裝飾一個字詞**，含斜體、襯線、上色、底線。 | 一種字體、一個色彩，靠文字強調。 |
| **最多兩種字體，通常一種。** | 抽選字型系統。 |

檢查器保留三種例外：`<pre>`/`<code>` 中真實程式碼可等寬；真實表格、表單欄位可有線；根節點有 `data-ui` 的真實介面片段保留產品邊框與選單，見 `references/imagery.md` §7。

誠實說明理由：部分來自研究，247 站中評分至少 7.5 相較低於 6.5 的網站，圖示功能卡 1% 對 28%、膠囊徽章 14% 對 34%、漸層 22% 對 52%、陰影 24% 對 48%、小型加寬大寫 16% 對 57%。其餘是作者偏好，甚至違反當代展示站潮流：等寬標籤、索引數字、髮絲格線在得獎站更多，生成器因此模仿，最終像套裝。此處一律禁止。`references/tells.md` 保留有日期的登錄。

移除裝飾留下空間，不再填另一種裝飾。改放大主體、補完整內容、加主題圖片或整片平色。每頁最多一次刻意留空。

## 設計原則

以下為摘要，除註明作者準則外，數字來自研究。

**字型**
- 兩三種字級主導：一個極大、一個小，中間不塞字級。標題／正文中位比 4.3；最佳網站更大，最大文字中位 8.4vw，弱站 5.0vw。
- 展示字字距 -0.02 至 -0.05em、行高 0.85–1.05。正文 16–20px、行高 1.45–1.6、每行 45–75 字元。
- 每頁最多五字級。單一家族常見，約三分之一；最多兩家族。
- 預設靠左，每頁最多一次置中。

**空間**
- 共用一套格線與緊湊邊界 16–32px，大元素延伸到邊，文字全頁共用兩三條左緣。
- 格線內非對稱，外框不變；兩外邊界相等，偏心標題在另一側有呼應。
- 區段間距明顯大於內部，桌面 120–240px，研究中位約 240。
- 相鄰區段不同構圖，皆非卡片格線。

**色彩**
- 一個底色、文字色、強調色。強調色用於行動，最多再一處。
- 正文用完整文字色，柔灰正文像未完成。
- 表面靠小色階分，不靠線、陰影。
- 區段可整片換色，不互相淡化。

**影像**
- 一張主圖勝過六小圖。高分站 68% 的主視覺媒體至少佔半個首屏。
- 相同裁切比例、處理方式；方向未另訂就直角，73% 研究站如此。
- 寧缺勿用佔位、圖示、抽象形狀。精心以主題色繪製更好；搜尋且署名的真實世界圖片更好。
- 搜尋圖片下載進專案，頁上署名、報告列出；不可冒充客戶自有。
- 不可遮住標題或陳述句，檢查器會判失敗。

**元件**
- 按鈕平面單色，直角或全圓一次決定。高分站 52% 直角、23% 膠囊；9–16px 柔圓角是弱站預設。強主視覺多半零或一按鈕。
- 導覽：文字標誌、三至五普通連結、一行動，不裝飾外框。
- 頁尾是設計過的收尾，非網站地圖；強站常用滿寬名稱回歸。

## 特殊情況

**既有品牌或設計系統。** 傳 `--keep palette,type`，品牌色與字型映射到角色，只抽構圖。準則仍適用；品牌本身要求禁用手法，如漸層標誌、紫色強調，保留品牌素材、報告說明，僅該項傳 `--allow <rule>`。

**既有網頁或 App 的改版、樣式調整、審查。**

1. **記錄修改前。** 啟動原專案，`inspect.mjs <url> --out .taste-skill/before`；App 加 `--app`，另 lint 原始碼。讀框架、Tailwind v3/v4、CSS modules、styled-components、純 CSS、元件，以及須保留的 routes、表單、資料、行為、自有品牌素材。
2. **只審查就停此。** 依 `references/critique.md` 評估修改前截圖，附量測列出發現，說明最有影響的三項變更。
3. **保留技術、內容與正常功能。** 不遷移框架或樣式庫；加依賴前檢查設定。樣式調整保留版型，只用抽選方向的字型、色彩、元件，品牌固定項用 `--keep`；改版則抽完整方向，在既有元件內重做藍圖區段。兩者都從步驟 2 用真內容繼續。
4. **最低風險最大效果順序：**字型與尺度、底／字／強調色、外框與節奏及標題、hover／focus／loading／empty／error 狀態，最後以藍圖換掉圖示卡、膠囊徽章、漸層球、卡片格線。
5. **證明。** 重跑到 `.taste-skill/after`，每寬度前後比較，逐一點原本可用連結、表單、選單，並列回報量測。

**單一元件或區段。** 有方向就略過抽選，配合周圍設計、套準則，仍要檢查。

**沒有結帳或表單後端。** 需求有真目的地就連過去；否則用帶主旨、內文與訪客選擇的 `mailto:`。商店可指向 `#checkout`，報告明說上線前須接線，不偽造付款表單。

**沒有 Chrome 或 Node 22。** 跑 `lint.mjs`，需 Node 18+；用現有瀏覽器工具截圖、評估，回報檢查器無法執行。

**沒有網路。** `assets.mjs` 所有來源均不可達時，改繪製並回報無法搜尋開放典藏。
